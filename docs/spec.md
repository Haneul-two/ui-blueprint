## 1. 목표

- **무엇을**: UI/UX 기능을 블록으로 모은 웹사이트. 사용자가 블록을 골라 아트보드 위 원하는 자리에 놓고 크기·내용·스타일을 바꾸며 대시보드·웹사이트·앱 화면을 설계한다.
- **누가 쓰나**: 주소를 아는 누구나(공개 정적 사이트). 기획자·개발자·디자이너가 시안을 빠르게 맞춰 볼 때.
- **어느 수준**: 편집기 조작감은 Figma·Framer 같은 아트보드 편집기의 기본(끌기·크기 조절·스냅·실행 취소·레이어). 블록 품질은 stageshow 키트와 하늘 창고 디자인 선반 레퍼런스.
- **산출물**: 이 저장소의 React+TS+Vite 정적 사이트. `npm run build` 결과 `dist/`를 어떤 정적 호스팅에도 올릴 수 있다. 사용자가 가져가는 것: 설계 JSON, PNG 이미지, 보기 전용 공유 링크, AI용 사양서(Markdown).

## 2. 우선순위와 순서

하위 프로젝트 3개를 순서대로 완성한다.

### A. 블록 라이브러리
- P0: 블록 규격(`BlockDef`, 아래) 하나로 목록·속성 패널·기본값·사양서 문구가 모두 파생된다. 블록 40개 이상, 분류 7개(레이아웃·데이터·입력·피드백·콘텐츠·모션·기기 틀). 모든 블록은 기본값만으로 깨지지 않고 그려진다. 미리보기 모드에서 상호작용 블록(탭·토글·아코디언·모달·폼 검증·드롭다운·체크리스트·세그먼트·캐러셀 등)이 실제로 동작한다.
- P1: 블록마다 출처 표시(stageshow 키트 / 참고한 레퍼런스의 기법 이름). 라이트·다크 둘 다에서 읽힌다.
- P2: 블록 즐겨찾기.

#### BlockDef 규격
`{ type, name, category, icon(lucide 이름), size:{w,h}, minSize:{w,h}, props: PropField[], defaults, interactive:boolean, motion:boolean, source:string, describe?(props)=>string, Render }`
- `PropField.kind`: `text` · `textarea` · `number`(min·max·step) · `select`(options) · `toggle` · `color` · `list`(줄마다 한 항목, 최대 50줄).
- `Render({props, mode, still})`: `mode`가 `edit`이면 상호작용을 하지 않는다. `still`이 참이면(움직임 줄이기·PNG 만들기) 모션을 끝 상태로 그린다.
- 블록별 속성의 정본은 각 블록 파일의 정의다. 사양서는 분류·개수·상호작용 여부를 정하고, 테스트가 정의의 유효성을 강제한다.
- 상호작용 필수 블록(미리보기에서 동작): 탭, 토글, 세그먼트, 드롭다운, 체크리스트, 가입 폼(빈 칸·이메일 형식 오류를 해당 칸 아래 표시, 고치면 사라짐, 통과 시 버튼이 "완료"), 모달(버튼 누르면 열림, Esc·닫기로 닫힘), 아코디언, 카드 캐러셀(이전·다음), 토스트(버튼 누르면 뜸), 툴팁(올리면 뜸), 입력칸·검색창(입력됨), 숫자 굴림(누르면 다음 값).
- "글자 효과"는 블록 하나이고 효과 종류(쪼개 등장·타자기·흐르는 그라디언트·글자 뒤집기)를 속성으로 고른다.

### B. 배치 편집기
- P0: 블록 목록(분류 탭 + 검색) → 끌어 놓기 또는 클릭으로 추가. 선택, 이동, 8방향 크기 조절, 8px 스냅. 속성 패널(위치·크기·블록 속성). 삭제·복제·앞으로/뒤로. 실행 취소/다시 실행. 편집 모드 ↔ 미리보기 모드. 아트보드 종류(데스크톱·태블릿·폰)와 높이 변경. 자동 저장.
- P1: 키보드 조작(화살표, Delete, Ctrl+Z/Shift+Ctrl+Z/Ctrl+Y, Ctrl+D, Ctrl+C/V, Esc). 레이어 패널(목록 선택·숨김·잠금·순서). 확대/축소·화면 맞춤. 정렬 안내선(다른 블록 가장자리·가운데에 붙기). 테마 조절판(강조색·모서리·글꼴·밀도·라이트/다크)과 CSS 변수 복사. 다중 선택(Shift+클릭) 후 함께 이동·삭제.
- P2: 다중 선택 정렬 버튼(왼쪽·가운데 맞춤 등).

### C. 저장·공유·내보내기
- P0: 여러 설계 관리(새로 만들기·이름 바꾸기·복제·삭제·목록), 브라우저 자동 저장. JSON 내보내기·불러오기(검사 통과한 것만). 공유 링크(설계를 압축해 주소 `#` 뒤에 담음) → 보기 전용 화면. PNG 내보내기. AI용 사양서(Markdown) 복사·내려받기. 프리셋 3개(대시보드·랜딩·앱 화면).
- P1: 보기 전용 화면에서 "내 설계로 복사". 공유 링크 길이 안내.
- P2: 없음.

### 안 만듦
- 로그인·서버 저장·갤러리: 1라운드 답(각자 브라우저 + 파일).
- 여러 명 동시 편집, 실데이터 연결, AI 자동 배치: 1라운드에서 제외 공개.
- HTML 코드 내보내기: 1라운드 답(이미지 + 링크 + AI용 사양서).
- 이미지 업로드: 공유 링크가 주소에 설계를 담는 구조라 그림을 넣으면 링크가 수 MB가 된다. 그림 자리는 자리표시 블록으로 둔다.
- 실제 배포: 완성 후 별도 승인(되돌리기 어려운 외부 공개).
- 실제 브랜드를 흉내 낸 블록·로고·아이콘: 사용자 요청.

### 만드는 순서와 확인 기준
1. 뼈대(Vite·타입·CONFIG·키트 사본) → `npm run build` 통과.
2. A: 규격 + 블록 40개 → 규격 검사 테스트(모든 블록 기본값으로 렌더, 속성 스키마 유효) 통과, 블록 견본 화면 캡처 확인.
3. B: 편집기 → 상태 로직 단위 테스트 + e2e(추가·이동·크기·실행 취소·미리보기 상호작용).
4. C: 저장·공유·내보내기 → 직렬화 왕복 테스트 + e2e(링크 열기·JSON 불러오기·PNG 생성·사양서).
5. 마감: 반응형·접근성·성능 확인, 교차 리뷰, 기록.

## 3. 흐름과 상태

### 화면 경로(해시 라우팅, 정적 호스팅에서 새로고침해도 깨지지 않게)
- `#/` 설계 목록(첫 방문이면 프리셋 3개 + 빈 설계 시작 카드)
- `#/edit/<id>` 편집기
- `#/view?d=<압축값>` 보기 전용(공유 링크)
- `#/blocks` 블록 견본(모든 블록 한 화면, 검증·둘러보기용)

### 편집기 상태
- `mode`: `edit` | `preview`. edit에서 블록 내부는 클릭이 막히고(포인터는 겉 상자가 받음) 선택·이동만 된다. preview에서는 선택 표시가 사라지고 블록 내부가 실제로 동작한다. 미리보기에서 바꾼 블록 내부 상태(탭 위치 등)는 설계에 저장하지 않는다.
- `selection`: 블록 id 배열. 빈 곳 클릭 = 비움. Shift+클릭 = 추가/빼기. 숨긴 블록은 캔버스에서 선택 불가(레이어 패널에서만), 잠근 블록은 선택은 되고 이동·크기 조절은 안 된다.
- 드래그: 포인터 누름 → 3px 넘게 움직이면 시작(그 전 떼면 단순 선택). 진행 중 `buttons===0`이면 종료 처리. 놓을 때 한 번만 기록(실행 취소 1단계). Esc를 누르면 드래그 시작 전 위치로 되돌린다.
- 겹침 순서: `items` 배열 순서가 곧 위아래 순서(뒤가 위). 새 블록은 맨 위. 그룹 묶기는 안 만든다.
- 아트보드 높이: 가장 아래 블록의 끝(y+h)보다 작게 줄일 수 없다(입력값을 그 값으로 올림).
- 아트보드 종류 변경(폭 변경): 블록 폭이 새 폭보다 크면 새 폭으로 줄이고, 오른쪽 끝이 넘치면 x를 당긴다. 한 번의 실행 취소 단계.
- 크기 조절: 최소 크기는 블록 정의의 `minSize`, 아트보드 밖으로 못 나간다(위치는 0 이상, 오른쪽 끝은 아트보드 폭 이하).
- 목록에서 끌어 놓기: 아트보드 위에 놓으면 그 자리(스냅), 밖에 놓으면 취소. 클릭으로 추가하면 현재 보이는 영역 가운데, 다른 블록과 겹치면 24px씩 비켜서 놓는다.
- 실행 취소: 설계 변경(추가·삭제·이동·크기·속성·순서·숨김·잠금·아트보드·테마) 단위. 속성 입력은 입력칸에서 포커스가 빠질 때 또는 400ms 멈췄을 때 한 단계로 묶는다. 선택 변경은 기록하지 않는다.
- 자동 저장: 변경 400ms 뒤 localStorage에 저장. 저장 직전 저장본을 다시 읽어 다른 탭에서 바뀐 **다른 설계**는 덮어쓰지 않는다(설계별 키로 나눠 저장해 충돌 범위를 줄임). 같은 설계를 두 탭에서 고치면 마지막 저장이 이기고, 다른 탭에서 바뀌면 "다른 탭에서 바뀌었습니다. 새로 불러오기" 안내를 띄운다.
- 예외: localStorage 쓰기 실패(용량·사생활 모드) → 상단에 "브라우저에 저장하지 못했습니다. JSON으로 내보내 두세요" 경고, 편집은 계속.

### 공유·불러오기
- 공유 링크: `{v:1, design}` JSON → `CompressionStream('deflate-raw')` → base64url. 열 때 역순. 결과가 `shareMaxLength`를 넘으면 링크를 만들지 않고 "블록이 많아 링크에 담을 수 없습니다. JSON 파일로 보내 주세요" 안내 + JSON 내보내기 버튼.
- 보기 전용 화면: 아트보드를 창 폭에 맞춰 비율 축소(최대 1배), 세로는 스크롤. 블록은 미리보기 모드로 동작한다. 풀기 실패·검사 실패 → "링크가 깨졌거나 이 버전에서 열 수 없습니다" 화면 + 목록으로 가기.
- JSON 불러오기: 검사기(`validateDesign`)를 통과해야 새 설계로 추가한다. 모르는 블록 종류는 "알 수 없는 블록" 자리표시로 그리고 알려 준다(지우지 않음).
- 검사기는 숫자 범위, 문자열 길이(속성 문자열 2,000자, 목록 50개), 블록 수(500개)를 막는다.

### 빈 상태·로딩·오류
- 설계 목록이 비면 프리셋 카드와 "빈 설계로 시작".
- 블록 검색 결과 없음 → "맞는 블록이 없습니다" + 검색어 지우기 버튼.
- 아트보드가 비면 가운데 안내 "왼쪽에서 블록을 끌어다 놓으세요".
- PNG 만들기 중 버튼은 "만드는 중…" + 비활성, 실패하면 토스트로 사유.

## 4. 내용

- 사이트 이름: **UI 설계도**. 부제: "블록을 골라 놓으며 화면을 설계해 보세요."
- 블록 안 글은 일반적인 예시 문구(가상 서비스 "하루 노트", 숫자는 그럴듯한 예시값). 실존 기업·제품 이름, 로고는 쓰지 않는다.
- 블록 분류와 목록(40개 이상, 확정 목록은 `src/blocks/` 각 파일의 정의가 기준):
  - 레이아웃: 상단 메뉴, 사이드바, 섹션 제목, 빈 패널, 구분선, 벤토 그리드, 푸터
  - 데이터: KPI 카드, 선 차트, 막대 차트, 도넛 차트, 표, 진행 막대, 활동 피드
  - 입력: 버튼, 입력칸, 검색창, 토글, 세그먼트, 탭, 드롭다운, 체크리스트, 가입 폼(검증)
  - 피드백: 토스트, 알림 배너, 모달, 툴팁, 빈 상태, 스켈레톤 로딩, 배지 묶음
  - 콘텐츠: 히어로, 기능 카드, 가격표, 후기, 아바타 묶음, 타임라인, 이미지 자리, 글 단락, 자주 묻는 질문(아코디언), 채팅, 카드 캐러셀
  - 모션: 글자 효과(쪼개 등장·타자기·흐르는 그라디언트·글자 뒤집기), 숫자 굴림, 흐르는 띠, 스포트라이트 카드
  - 기기 틀: 브라우저 창, 휴대폰, 터미널
- AI용 사양서 형식: 제목, 아트보드 크기·테마 토큰, 블록 목록(위→아래, 왼→오 순서: 이름·종류·위치·크기·속성), 상호작용 설명, 마지막에 지시 문단: "좌표는 이 아트보드 폭 기준의 시안 배치다. 같은 배치를 기준 화면으로 삼아 React/HTML로 구현하되, 좁은 화면에서는 위→아래 순서로 쌓이는 반응형으로 만들어 주세요."

## 5. 품질 기준

기술 통과(테스트·측정):
1. `npm run build`와 `npm run typecheck`가 오류 0으로 끝난다.
2. `npm test`: 모든 블록이 기본값으로 렌더된다(예외 0), 속성 스키마가 유효하다, 블록 수 ≥ 40, 분류 7개 모두 블록 ≥ 3.
3. 직렬화 왕복: 프리셋 3개를 JSON·공유 링크로 보냈다 받으면 원본과 깊은 비교가 같다.
4. 검사기: 잘못된 JSON 픽스처 6종(형식 오류, 숫자 범위, 문자열 길이, 블록 수, 모르는 블록, 버전 불일치)을 모두 기대대로 처리한다.
5. e2e(`npm run e2e`): ① 블록을 끌어 놓으면 놓은 자리에 8의 배수 좌표로 생긴다 ② 크기 조절 후 w·h가 8의 배수이고 minSize 이상 ③ Ctrl+Z가 직전 한 단계만 되돌린다 ④ 미리보기에서 탭·토글·아코디언·모달·폼 검증이 동작하고 편집 모드에서는 동작하지 않는다 ⑤ 새로고침 후 설계가 남아 있다 ⑥ 공유 링크를 새 컨텍스트에서 열면 같은 블록 수·위치로 보기 전용 화면이 뜬다 ⑦ PNG 내보내기 결과가 가로·세로 = 아트보드 × `pngScale`이고, 이미지 픽셀의 서로 다른 색이 16가지 이상(빈 그림 아님)이며 모션 블록은 끝 상태로 찍힌다(`still` 모드로 렌더 후 촬영) ⑧ 콘솔 오류 0.
6. 1440×900에서 편집기 세 칸(블록 목록·캔버스·속성)이 모두 보이고 가로 스크롤 없음. 390×844에서 목록·보기 전용 화면은 가로 넘침 없음, 편집기는 "편집은 넓은 화면에서" 안내 + 미리보기만.
7. 글자 대비: 편집기 화면과 `#/blocks`(블록 전부)의 글자 노드마다 글자색과 실제 배경색(조상 중 처음 나오는 불투명 배경)으로 WCAG 대비를 계산한다. 24px 미만 4.5:1, 24px 이상 또는 18.66px 굵은 글씨 3:1 이상. 라이트·다크 둘 다. 배경이 그라디언트·그림인 노드와 장식용 자리표시 막대(`aria-hidden`)는 빼고 뺀 개수를 기록한다(e2e 안에서 측정).
8. 키보드만으로 블록 추가(목록에서 Enter)·선택(레이어 패널)·이동(화살표)·삭제가 된다(e2e). 편집기·목록·보기 화면의 모든 `button`·`[role=button]`·`a`·입력칸에 접근 가능한 이름(글자, aria-label, label, title 중 하나)이 있다(e2e가 전수 검사).
9. `prefers-reduced-motion`이면 모션 블록이 마지막 상태로 멈춰 그려진다: e2e가 `emulateMedia({reducedMotion:'reduce'})`로 `#/blocks`를 열고 모션 블록 안 `getAnimations()` 실행 중 개수 0, JS 타이머 연출도 멈춤(1초 사이 글자 변화 없음).
10. 공개 결과물(`src`, `dist`, `docs`)에 절대 경로·로컬 폴더명·회사명이 0건(금지어 검사 스크립트).
11. 참고 측정(합격 기준 아님): 블록 전부를 놓은 회귀 설계에서 이동 드래그 60프레임의 프레임 간격 중앙값을 기록한다. 33ms를 넘으면 원인을 찾아 고친다.

조형 의견(합격 판정 아님, 캡처로 직접 보고 판단):
- 블록 견본 화면에서 블록들이 같은 계열로 보이는지, 와이어프레임처럼 비지 않는지.

## 6. 금지와 이유

- 실존 브랜드를 흉내 낸 블록·로고·앱 아이콘을 넣지 않는다. 안 그러면 사용자 요청 위반이고 상표 문제가 생긴다. stageshow `kit/brands/`와 `BrandMark`, `assets/app-icons.ts`는 복사하지 않는다.
- 하늘 창고·디자인 사이트 레퍼런스의 코드·글·이미지를 그대로 옮기지 않는다. 안 그러면 라이선스 문제가 생긴다. 구조와 기법만 가져와 새로 짠다.
- 예외: stageshow 키트(MIT)는 `kit/`을 `src/vendor/stageshow/`로 복사해 쓴다. `brands/`·`parts/BrandMark.*`는 빼고 `parts/index.ts`에서 그 내보내기만 지운다. 사본 폴더에 원본 `LICENSE`와 바꾼 내용을 적은 `NOTICE.md`를 둔다. 사본은 eslint·금지어 검사 대상에서 빼지 않는다.
- 아이콘 세트를 섞지 않는다. 안 그러면 선 두께·모양이 어긋난다. 키트가 이미 쓰는 lucide-react 하나로 통일한다(전역 DESIGN.md "기존 아이콘 세트가 있으면 혼용하지 않는다").
- 숫자 옵션에 `||` 기본값을 쓰지 않는다. 안 그러면 0이 기본값으로 바뀐다(`??` 사용).
- `display`를 준 요소에 `hidden` 속성만으로 숨기지 않는다. 안 그러면 안 숨는다(`[hidden]{display:none}` 함께). (규칙집 web-app)
- 모달(dialog)이 열린 동안 토스트를 body에만 붙이지 않는다. 안 그러면 top layer에 가려 안 보인다. (규칙집 web-app)
- Pointer 드래그는 move에서 `buttons===0`이면 끝낸다. 안 그러면 요소 밖에서 손을 뗀 뒤 버튼 없이 지나가도 드래그가 이어진다. (규칙집 web-app)
- JS로 움직이는 연출은 `prefers-reduced-motion`을 JS에서도 확인한다. 안 그러면 CSS 규칙이 못 잡는다. (규칙집 web-app)
- 상태 표시를 opacity로 흐리지 않는다(숨긴 레이어 등). 안 그러면 대비가 무너진다. 아이콘·취소선으로 표시한다. (규칙집 web-app)
- 역할 없는 div에 aria-label을 달지 않는다. (규칙집 web-app)
- 비동기 결과(클립보드 복사, PNG 생성)는 세대 번호로 늦게 온 결과를 버린다. 안 그러면 닫은 패널에 결과가 되살아난다. (규칙집 web-app)
- 공개물에 절대 경로·로컬 폴더명·회사명을 쓰지 않는다. 금지어 목록은 git에 넣지 않는 `scripts/forbidden.local.txt`에 둔다. 안 그러면 목록 자체가 공개된다. (규칙집 public-output)
- Python으로 소스를 쓰지 않는다(CRLF). Node에 넘기는 윈도 경로는 드라이브 문자 + 슬래시 형식으로 쓴다. `node --test`에 폴더를 넘기지 않는다. (규칙집 dev-env)
- 검사 기대값을 데이터 개수에 박지 않고 레지스트리에서 계산한다. (규칙집 web-verify)
- 해당 없어 뺀 규칙: 캔버스 점 수천 개 그리기, 사진+격자 겹침, 칸 넘기기 inert(캐러셀 블록은 미리보기용 장식이라 키보드 대상 아님. 단 캔버스 밖 화면에는 해당 없음), Next.js·Cloudflare 규칙(정적 Vite).

## 7. 검증 방법

- `npm run typecheck`, `npm run build`, `npm test`(vitest, jsdom).
- `npm run e2e`: `scripts/e2e.mjs`가 `vite preview`를 띄우고 설치된 Chrome(`playwright-core`, `channel:'chrome'`)으로 위 5번 ①~⑧을 돌린다. 캡처는 `shots/`(git 제외)에 1440×900·390×844.
- 디버그 훅: `#/edit/<id>?fixture=<이름>`으로 고정 설계를 불러온다(프리셋 3개 + `all-blocks` 회귀 설계). 상태는 블록 겉 상자의 `data-id`·`data-type`과 인라인 위치(left·top·width·height)로 읽는다(별도 전역 훅 없음).
- 대비: `scripts/contrast.mjs`가 토큰 색 쌍을 WCAG 공식으로 계산.
- 금지어: `scripts/check-public.mjs`(목록은 `scripts/forbidden.local.txt`, 없으면 경고 후 사용자 폴더 경로 패턴만 검사).

## 8. 가정

- React 18 + TS + Vite, 해시 라우팅. 뒤집으려면 `src/app/router.ts`.
- 배치는 반응형 격자가 아니라 아트보드 위 자유 배치(8px 스냅). "원하는 대로 배치"를 가장 직접 만족. 기기별로 다른 배치를 쓰려면 설계를 복제해 아트보드를 바꾼다. 뒤집으려면 `Design.items` 구조를 기기별로 나눈다.
- 공유는 주소 해시에 압축해 담는다(서버 없음). 뒤집으려면 `src/io/share.ts`.
- PNG는 `html-to-image`(MIT)로 만든다. 뒤집으려면 `src/io/png.ts`.
- 아이콘은 lucide-react(키트와 통일). 전역 기본 Tabler 대신 쓰는 이유는 6장.
- 편집기 외관 토큰: 라이트 바탕 `#eef1f5`(차가운 제도 용지), 면 `#ffffff`, 글자 `#16213a`, 보조 글자 `#4f5b70`, 선 `#d3dae4`, 강조 `#1f4fd1`. 다크 바탕 `#10141c`, 면 `#181e29`, 글자 `#e6eaf2`, 보조 `#a0abbd`, 선 `#2a3342`, 강조 `#8aa8ff`. 따뜻한 크림색은 생성형 화면의 흔한 기본값이라 피했다. 인상 요소는 하나: 선택한 블록에 도면식 치수선(폭·높이 숫자). 글꼴 `Pretendard, system-ui, "Malgun Gothic", sans-serif`(웹폰트 내려받지 않음). 대비는 5장 7번으로 확인. 뒤집으려면 `src/styles/tokens.css`.
- 디자인 탐색: 공개 사이트지만 성격이 편집 도구라 전역 DESIGN.md의 "경량" 강도로 하고, 시안 갤러리 정지점 대신 편집기 안의 테마 조절판(P1)을 조절판으로 쓴다. 착수 후 묻지 않는다는 사용자 규칙을 따른 판단. 편집기 외관 컨셉: "청사진". 제도 용지 바탕, 점 격자 캔버스, 코발트 강조 하나.
- 블록 안 예시 문구는 가상 서비스 "하루 노트". 뒤집으려면 각 블록의 `defaults`.
- 다른 탭과의 충돌은 설계별 키 + "다른 탭에서 바뀜" 안내로 처리(자동 병합 없음).
- 배포 대상(GitHub Pages 등)은 완성 후 승인받을 때 정한다. `vite.config.ts`의 `base: './'`로 어느 경로에서도 열리게 둔다.
